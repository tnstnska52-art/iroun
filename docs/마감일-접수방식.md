# 마감일 없는 공고의 접수 방식 · 지난 마감일 처리 (2026-11-23)

전산(go.irowoon.com) 계약자 화면에서 "마감일자가 제대로 읽히지 않는다"는 문의로 운영 공고를 확인한 결과와 고친 내용이다.

## 확인한 것 (신청 가능 목록 2,147건)

| 구분 | 건수 |
| --- | --- |
| 마감일이 날짜로 있는 공고 | 835 |
| 그중 마감일이 이미 지났는데 상태가 `접수 중`·`확인 필요`로 남은 공고 | 586 |
| 마감일이 없는 공고 (거의 모두 상태 `상시 조회`) | 1,312 |

- 마감일이 없는 기업마당 공고의 원문 신청기간은 「예산 소진시까지」「상시 접수」였다. 날짜를 못 읽은 것이 아니다. 다만 AI 정리(`applyAi`)가 마감일이 없으면 모두 `상시 조회`로 적어서 두 가지가 구분되지 않았다.
- 공고 상태는 수집·정리할 때 한 번 정해진다. 그 뒤 마감일이 지나도 원문이 그대로면 다시 계산하지 않아 `접수 중`으로 남는다.

## 고친 것

### 접수 방식 `deadlineKind`

공고 자료에 선택 항목을 하나 더했다. 마감일(`endsAt`)이 없을 때만 쓴다.

| 값 | 뜻 | 원문 표현 예 |
| --- | --- | --- |
| `budget` | 예산 소진 시까지(먼저 끝날 수 있음) | 예산 소진시까지, 선착순, 상시 접수(예산 소진 시 조기 마감) |
| `always` | 상시 접수 | 상시 접수, 연중 수시 |
| `unknown` | 원문에서 기간을 읽지 못함 | 세부사업별 상이 |

- 기업마당: `reqstBeginEndDe`, 정부24 사업자 서비스: `신청기한` 글에서 읽는다(`deadlineKindOf`).
- 본문이나 AI 정리에서 마감일을 찾으면 이 값을 뺀다.
- **이미 저장된 공고**: 원문이 그대로인 공고는 매시간 수집 때 확인 시각만 고치는데(`refreshOfficialCheck`), 이때 마감일이 빈 공고에 한해 이 값을 채운다. 다른 항목과 공개 상태는 건드리지 않는다. 기업마당은 수집 쪽수를 나눠 돌므로 전부 채워지는 데 몇 시간이 걸린다.
- 직접 넣은 상시 제도(`standing-programs.ts`)는 사업마다 예산 마감 여부를 확인하지 않아 값을 넣지 않았다.
- 공고 상태(`status`)와 예산 상태(`budgetStatus`)의 뜻은 바꾸지 않았다. 앱·홈페이지의 맞춤 판단에 쓰이는 값이라 영향이 크다.

### 마감일이 지난 공고

`/api/public/check-benefits` 목록을 만들 때 마감일(한국 날짜)이 지난 공고는 상태와 상관없이 마감(`past`)으로 보내고 상태를 `마감`으로 적는다(`expired`, `partOf`). 저장된 자료는 바꾸지 않는다. 마감일 당일까지는 접수 중이다.

홈페이지 조회 화면과 전산은 이미 마감일로 한 번 더 걸러 보여 주고 있어서 화면 결과는 같다. 신청 가능 목록이 586건 가벼워지고, 마감 목록에 최근 마감 공고가 빠지지 않는다.

## 되돌릴 때 주의

공고 자료 검사(`benefitSchema`)는 모르는 항목을 거부한다. 이 변경이 배포돼 `deadlineKind` 가 저장된 뒤 이전 버전으로 되돌리면 그 공고를 다시 저장하는 작업(AI 정리, 관리자 수정)이 실패한다. 되돌려야 하면 먼저 값을 지운다.

```sql
UPDATE iroun_benefits SET data = data - 'deadlineKind' WHERE data ? 'deadlineKind';
```
