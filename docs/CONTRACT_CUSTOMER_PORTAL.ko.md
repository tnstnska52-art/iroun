# 계약 고객 창구: 모바일 웹·PC·설치 앱

회사에서 발급한 아이디와 비밀번호로 이용하는 고객 창구는 https://go.irowoon.com/package-conditions 입니다. 지원사업 신청, 서류 교체, 회사와의 대화는 이 창구의 CRM 자료를 사용합니다.

## 2026-11-12 결정: 앱 전체 = 고객 창구 (계약 고객 전용 앱)

대표 결정으로 설치 앱은 켜자마자 고객 창구(https://go.irowoon.com/package-conditions)를 **앱 화면 전체**로 엽니다. 하단 탭·지원금 찾기·Clerk 로그인은 이 모드에서 쓰지 않습니다.
- 모드 스위치: `lib/app-mode.ts`. 기본 `portal`. `EXPO_PUBLIC_APP_MODE=benefits`로 빌드하면 예전 지원금 앱(탭 구조)으로 돌아갑니다. 미리보기(`EXPO_PUBLIC_PREVIEW=1`)는 예전 앱입니다. 예전 코드는 지우지 않았습니다.
- 화면: `components/PortalView.tsx`(WebView). 아래 '내 계약' 탭 설명의 동작(쿠키 로그인 유지, 외부 주소 넘기기, 파일 올리기·내려받기, 뒤로가기, 실패 시 다시 열기)을 그대로 씁니다.
- 알림(`lib/portal-push.ts`): 처음 켤 때 알림 허용을 묻고, 허용하면 Expo 알림 주소를 창구에 `window.IROUN_APP = { app:'iroun', bridge:1, platform, pushToken }`와 `iroun-app` 이벤트로 알립니다. 알림의 `data.url`(회사 창구 https 주소만)을 누르면 그 화면을 엽니다. 알림 발송과 계정 연결은 **전산(CRM) 쪽 작업**입니다.
- 웹에서 이 모드는 창구 주소로 바로 이동합니다.

## 2026-11-12 변경: 앱 안의 '내 계약' 탭 (benefits 모드)

설치 앱의 하단 탭에 **내 계약**을 두고(환급금 탭 자리, 환급금은 홈의 '환급금 전체 보기'로 이동), 고객 창구를 **앱 화면 안(WebView)** 에서 엽니다.
- 회사 고객 창구(*.irowoon.com, https)만 앱 안에서 열고, 기관 사이트·전화·카카오 등 다른 주소는 휴대폰 브라우저·앱으로 넘깁니다.
- 로그인은 창구의 '로그인 유지' 쿠키(__Host-package_session, HttpOnly)를 그대로 씁니다. 앱은 아이디·비밀번호·토큰을 다루지 않습니다.
- 서류 올리기는 창구의 파일 선택(PDF·사진·카메라)을 그대로 씁니다. iOS 카메라·사진첩 사용 문구와 Android CAMERA 권한을 추가했습니다.
- 서류 내려받기(blob + download)는 앱이 가로채 휴대폰 공유 창(저장·열기)으로 넘깁니다.
- Android 뒤로가기는 창구 안 이전 화면으로 갑니다. 열기 실패 시 '다시 열기'와 '브라우저로 열기'를 보여 줍니다.
- 앱 웹 버전에서는 기존처럼 같은 탭으로 창구를 엽니다.
- 새 네이티브 모듈(react-native-webview, expo-file-system, expo-sharing)이 들어가 **새 설치 파일 빌드가 필요**합니다. 실기기 확인 전에는 네이티브 동작을 성공으로 보지 않습니다.

(이전) 설치 앱의 홈·내혜택·내 정보에 **계약 고객 서비스 → 내 신청·대화 열기**를 추가했습니다. Clerk 가입 또는 휴대폰 로그인을 먼저 요구하지 않습니다. iOS에서는 Safari 화면, Android에서는 Custom Tab으로 같은 고객 창구를 열고, 앱의 웹 버전에서는 같은 탭으로 이동합니다. 화면을 닫으면 앱으로 돌아옵니다. 열기에 실패하면 다시 열기와 기본 브라우저로 열기를 제공합니다.

앱의 Clerk 계정과 CRM 계정은 서로 다른 인증 체계입니다. 자동으로 연결했다고 가정하거나 토큰·전화번호를 URL로 보내지 않습니다. iOS 앱 안의 Safari 화면은 일반 Safari와 로그인 쿠키가 다를 수 있으므로 처음에는 회사에서 받은 계정으로 로그인해야 합니다. 포털의 로그아웃과 로그인 유지 정책을 사용합니다.

기존 앱의 신청 기록·문의·서류 API와 이력을 변경하거나 CRM으로 이관하지 않습니다. 이 변경의 공통 고객관리 대상은 **계약 고객 서비스에서 진행한 신청과 대화**입니다. 기존 앱의 종 알림 및 푸시와 CRM 알림을 통합하는 변경도 아닙니다. CRM 답변은 고객 창구 안의 별도 답변 안내로 확인합니다.

## 검증과 배포

- 순수 이동 로직: `node --experimental-strip-types --test artifacts/iroun-benefits/lib/customer-portal.test.ts` (저장소 루트).
- 빠른 중복 클릭, iOS 닫기/취소, Android 열기, 웹 같은 탭 이동, 실패 후 재시도 및 명시적 브라우저 대체 경로를 검사합니다.
- `expo-web-browser`는 기존 의존성을 사용합니다. 새 SDK·권한·비밀키·DB 변경이 없습니다.
- 웹 고객 화면의 공개 버전과 앱 설치 파일의 배포는 별개입니다. GitHub에 코드가 반영되어도 설치된 앱은 자동으로 바뀌지 않습니다.
- 배포 전에 기존 EAS 프로젝트에서 새 설치 파일을 빌드하고 iPhone·Android 기기에서 로그인, 파일 선택/교체, 다운로드, 키보드, 닫기/복귀를 확인해야 합니다. 테스트는 가짜 고객 계정으로 진행합니다.
- 이번 작업 환경에는 Expo 빌드 인증 및 Android/iOS 실기기 환경이 없어 설치 파일 생성·스토어 제출·실기기 성공을 확인하지 않았습니다.
