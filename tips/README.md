# 지원금 꿀팁 자동 발행 운영 규칙

매일 예약 작업이 이 문서를 그대로 따른다. 사람이 규칙을 바꾸려면 이 문서만 고치면 된다.

- 게시판: https://www.irowoon.com/tips (아임웹 게시판 '지원금 꿀팁')
- 목적: 사장님들이 구글·네이버에서 지원사업을 검색했을 때 이 게시판 글이 노출되게 한다
- 브랜치: 이 저장소의 `tips-content` 브랜치에서만 작업한다. `main`은 건드리지 않는다.
- 관련 글 주소: 새 글 주소(idx)는 발행 뒤에야 알 수 있다. 같은 날 여러 글을 올릴 때는 하나씩 발행하고, 앞 글의 주소를 다음 글의 `related`에 넣는다.

## 파일

| 파일 | 역할 |
|---|---|
| `tips/registry.json` | 발행한 지원사업 목록. 중복 방지와 변경 점검의 기준 |
| `tips/posts/<날짜>-<영문약어>.json` | 글 원본 (내용만) |
| `tips/build.py` | 글 원본 → 아임웹 본문 HTML (`tips/html/<slug>.html`에 생성, 저장소에 함께 올림) |

## 하루 순서

1. **로그인 확인**: 앱 브라우저로 https://irowoon.com/admin/contents/post 를 연다. 로그인 화면이 나오면 거기서 멈추고 사장님께 "아임웹 로그인이 풀렸다"고 알린다. 비밀번호는 절대 입력하지 않는다.
2. **변경 점검** (아래 '변경 반영')
3. **새 글 최대 5개** (아래 '새 글 고르기' → '글 쓰기' → '발행'). 하루 발행 상한은 5개다(registry의 `published` 날짜로 센다). 이미 5개를 올린 날은 새 글을 더 올리지 않는다.
4. `registry.json`과 글 원본을 커밋해 `tips-content`에 올린다.
5. **인스타 카드뉴스 3개** (아래 '인스타 카드뉴스'). 아임웹 로그인이 풀려 글을 못 올린 날에도 기존 글로 카드뉴스는 만든다.
6. 결과를 짧게 보고한다: 새 글 제목·주소, 변경 반영한 글, 건너뛴 사업과 이유, 인스타 대기열에 올린 카드뉴스 3개 제목.

## 인스타 카드뉴스 (매일 3개, 승인 없이 자동 게시)

사장님 결정(2026.11.27): 승인·메일 없이 매일 자동으로 @irowoonsubsidy 에 3개 올린다. 자세한 형식은 `tips/cards/README.md`.

1. **고르기**: `registry.json`에서 `insta` 기록이 없는 글 3개. 오늘 새로 올린 글을 먼저, 모자라면 오래된 글 순. `status`가 `closed`인 글, 글에 '신청 전 확인 필요' 변경 안내만 있고 핵심 숫자가 미확인인 글은 고르지 않는다.
2. **카드 내용 쓰기**: `tips/cards/sets/<오늘 날짜>/<slug>/card.json` (예시 `tips/cards/sets/sample/voucher/card.json`).
   - 썸네일 1장 + 본문 4장(`list` 조건 3개 → `grid` 금액 4칸+노란 큰 숫자 → `x` 못 받는 경우(dark) → `steps` 신청방법). 마지막 팔로우 장은 자동.
   - 썸네일 후킹: 숫자(예: "딱 3가지"), 손실회피(예: "모르면 못 받는 25만 원"), 상반되는 개념(예: "사장님이 받는 실업급여"), 이유·방법 중 글에 맞는 하나. 강조 줄은 `*`로 시작(파란 띠).
   - 숫자·대상·기간·신청처는 그 글 원본과 `key_facts`에 있는 것만. 과장 표현 금지(생성기가 막음). 이로운사람들이 정부기관이거나 신청을 대신하는 것처럼 쓰지 않는다.
   - 카드에는 하단 작은 글씨를 넣지 않는다.
   - `caption`: 후킹 한 줄 → 핵심 2~3줄 → ✅ 요점 3개 → 🔔 팔로우 / 👆 프로필 링크 예상 지원금 안내 → 해시태그 8~10개. **"※ 출처"와 "※ 이로운사람들은 정부기관이 아니며…" 줄은 넣지 않는다**(사장님 결정 2026.11.27). 해시태그는 항상 넣는다(#이로운사람들 포함).
3. **만들기**: `cd tips/cards && npm i` (처음 한 번) → `node tips/cards/render.mjs tips/cards/sets/<날짜>/<slug>/card.json`. 오류(넘침·과장 표현)가 나면 문구를 줄여 다시 만든다. 썸네일(1.jpg)을 열어 글자가 잘리지 않았는지 눈으로 확인한다.
4. **대기열**: `tips/cards/queue.json` 의 `items` 끝에 3개를 `{"set": "sets/<날짜>/<slug>", "status": "pending", "post": "<registry key>"}` 로 추가하고, `registry.json` 해당 글에 `"insta": {"set": "...", "queued": "<날짜>"}` 를 적는다.
5. 카드 파일·queue.json·registry.json 을 한 커밋으로 `tips-content` 에 push 한다. push 하면 GitHub Actions 가 곧바로 첫 개를 올리고 2시간 30분 간격으로 나머지를 올린다(게시 결과 permalink 는 queue.json 에 자동 기록).
6. 다음 날 실행 때 queue.json 에서 전날 항목이 `posted` 인지 확인한다. 실패(`pending` 그대로이거나 Actions 실패)면 보고에 적고 알린다. 토큰은 GitHub Secret `IG_ACCESS_TOKEN` 에만 있고 저장소에 쓰지 않는다.

## 새 글 고르기

- 후보 출처: 기업마당(bizinfo.go.kr) 지원사업 공고, 소상공인24(sbiz24.kr) 공고, 중소벤처기업부·소상공인시장진흥공단·고용노동부·지자체 공고.
- 대상: 소상공인·자영업자·중소기업 사장님이 받을 수 있는 지원금, 바우처, 정책자금(융자), 폐업·재창업·고용·판로·디지털 전환 지원.
- **중복 금지**: `registry.json`의 `key`(연도-사업명)와 사업명·공고명을 비교해 이미 있는 사업은 쓰지 않는다. 같은 사업의 세부 항목(예: 같은 공고 안의 다른 지원 항목)도 새 글로 쪼개지 않고 기존 글의 변경으로 다룬다.
- 접수가 이미 끝난 사업은 쓰지 않는다. 단, 매년 반복되고 검색이 많은 사업(예: 경영안정 바우처, 희망리턴패키지)은 "다음 공고 대비" 글로 쓸 수 있다.
- 우선순위: 사장님이 많이 검색할 사업 > 접수 마감이 가까운 사업 > 지원 대상이 넓은 사업.
- **하루 최대 5개**: 3개는 전국 단위 사업을 우선한다. 나머지 2개는 전국 단위 사업이나 검색이 많은 광역 시·도 단위 사업(예: 서울·경기 소상공인 지원)으로 채운다. 기초 시·군·구 단독 공고, 같은 사업을 지역별로 쪼갠 비슷한 글은 쓰지 않는다. 공고 원문으로 확인되는 좋은 후보가 모자라면 5개를 억지로 채우지 않고 확인된 만큼만 올린다.
- **공고 원문 확인 필수**: 대상·금액·기간·신청처를 공고 원문(정부·공공기관 사이트, 기업마당 공고 상세)에서 확인한다. 블로그·카페 글만으로는 쓰지 않는다. 확인이 안 되면 그 사업은 `skipped`에 이유와 함께 적고 다음 후보로 넘어가 3개를 채운다. 3개를 못 채우면 채운 만큼만 올린다.

## 글 쓰기 (글 원본 JSON)

`tips/posts/2026-11-24-pyeup.json`과 같은 구조로 쓴다. 블록 종류: `p`, `note`(작은 회색 글), `h3`, `table`, `chart`, `steps`, `cards`, `list`, `warn`, `faq`. 표 칸에 `"O"`/`"X"`를 넣으면 ○ 가능 / ✕ 불가로 표시된다.

- **제목** (20~60자): 사장님이 검색창에 칠 문장을 앞에 둔다. 형식 예: `<사업명 또는 대표 검색어> 신청방법, <질문형 궁금증>? <핵심 숫자> 정리`. 이미 있는 글 제목과 겹치지 않게 한다.
- **첫 문장(intro)**: 아임웹에 메타 설명 칸이 없어서 첫 문장이 검색 결과 설명으로 쓰인다. 사업명, 핵심 금액, 누가 받는지를 80~150자 안에 담는다.
- **키워드**: 대표 검색어 1개 + 비슷한 검색어 4~6개. 대표 검색어는 제목·첫 문장·첫 번째 소제목에 들어가게 하고, 키워드마다 본문에 그대로 한 번 이상 나오게 한다(아임웹 'SEO 최적화 예상 점수'가 키워드의 제목·본문 포함 여부를 본다).
- **본문 구성** (섹션 4개 이상): 무엇을 주나 → 나는 받을 수 있나(상황별 ○/✕ 표) → 얼마 받나(표, 의미 있으면 계산 예시 그래프) → 신청방법(단계) → 준비 서류 → 놓치기 쉬운 점 → 자주 묻는 질문 4~5개(실제로 검색할 질문).
- **문장**: 짧고 쉽게. 어려운 행정 용어는 바로 풀어 쓴다. 숫자는 공고에 있는 것만 쓴다.
- **금지 표현**: "무조건", "100% 승인/지급", "확정 지급", "누구나 받는" 등 과장. 이로운사람들이 정부기관이거나 신청을 대행하는 것처럼 보이는 표현.
- **함께 보면 좋은 글** (`related`): 같은 게시판의 관련 글 2~3개를 `[[제목, 주소], ...]`로 넣는다. 글이 쌓일수록 서로 연결되어 검색에 유리하다. 관련 글이 없으면 생략.
- **마무리(cta)**: 버튼은 "내 지원금 확인하기"(https://www.irowoon.com/check#start) 고정. 문구는 글 주제에 맞게 한두 문장.
- **출처(sources)**: 공고명과 공고일, 확인한 날짜. 맺음말에 "이로운사람들은 정부기관이 아니며, 신청은 공식 사이트에서 직접" 문구를 넣는다.
- `python3 tips/build.py <글 원본>`이 오류 없이 끝나야 발행한다.

## 발행 (아임웹 관리자, 앱 브라우저)

1. https://irowoon.com/admin/contents/post → 왼쪽 목록에서 '지원금 꿀팁' 선택 → 오른쪽 위 '게시물 작성 ▾' → '새로운 글 쓰기'.
2. '제목' 칸에 제목, '키워드' 칸에 키워드를 쉼표로 구분해 입력.
3. 먼저 `tips/html/<slug>.html`을 커밋해 `tips-content`에 push 한다. 그다음 관리자 글쓰기 화면에서 JavaScript로 본문을 넣는다(가장 빠르고 정확함). 편집기는 `iframe.app` 안의 Froala 편집기다:
   ```js
   const d=document.querySelector('iframe.app').contentDocument;
   const ed=d.querySelector('.fr-box')['data-froala.editor'];
   const html=await (await fetch('https://raw.githubusercontent.com/tnstnska52-art/iroun/tips-content/tips/html/<slug>.html?_='+Date.now(),{cache:'no-store'})).text();
   ed.html.set(html); ed.events.trigger('contentChanged');
   // 확인: d.querySelectorAll('.fr-element h2').length 가 섹션 수와 같아야 한다
   ```
   이 방법이 안 되면 `</>`(코드 보기)에서 1만 자 이하로 나눠 직접 입력한다. 코드 보기의 textarea 값만 바꾸는 방법은 반영되지 않는다.
4. 화면을 내려 표·그래프가 보이는지 확인한다.
5. 오른쪽 위 '발행' → 게시판이 '[KR] 지원금 꿀팁'인지 확인 → '지금 바로 발행' → '발행하기'. ('점수 측정하기'를 누르면 패널이 길어져 '발행하기' 버튼 위치가 바뀐다.)
6. https://www.irowoon.com/tips 에서 새 글을 열어 본문이 나오는지 확인하고, 주소의 `idx` 값을 `registry.json`에 기록한다.

하지 않는 것: 다른 게시판·페이지·디자인 수정, 디자인 모드의 '게시하기', 글 삭제, 비밀번호 입력.

## 변경 반영

- 매일 `last_checked`가 가장 오래된 글부터 최대 10개를 점검한다. 공고 원문을 다시 열어 `key_facts`(대상·금액·기간·신청처)와 비교한다.
- 바뀐 것이 있으면 **기존 본문은 그대로 두고** 글 원본의 `updates`에 `{"date": "YYYY.MM.DD", "text": "신청기간 12.18 → 12.31 연장"}`처럼 한 줄을 추가하고 `updated` 날짜를 바꾼다. 생성기가 본문 맨 위에 '변경 안내' 상자를 만든다. 접수가 끝났으면 "접수 마감" 안내를 추가하고 `status`를 `closed`로 바꾼다.
- 아임웹에서 해당 글을 열어 '수정' → `</>` 코드 보기에서 전체 선택 후 삭제 → 새 HTML 입력 → 저장(발행). **글 주소(idx)는 바뀌면 안 된다.** 새 글로 다시 올리지 않는다.
- `registry.json`의 `key_facts`, `post.updated`, `last_checked`를 갱신한다. 바뀐 것이 없어도 `last_checked`는 갱신한다.
