# 이로운혜택 — 기존 앱 인수인계

이 폴더는 사용자가 직접 Claude에 넘기려는 기존 Replit 앱의 인수인계 자료다. 사용자는 비개발자이며, 같은 요구 설명과 체크포인트 승인을 반복하고 싶어 하지 않는다. 먼저 `00_START_HERE.txt`, `01_CLAUDE_START.txt`, `02_REQUIREMENTS.md`, `03_STATE_AND_ERRORS.md`, `04_ACCEPTANCE.csv`, `05_CONFIGURATION.md`를 읽어라.

## 첫 단계

1. 실제 앱 소스가 제공되었는지 먼저 확인한다. 자료 폴더나 참고 영상만 있고 프로젝트 소스가 없다면 앱을 새로 만들지 말고, 인계에 부족한 항목은 '실제 Replit 소스 압축파일' 하나로 명확히 알린다. 소스를 읽었다고 주장하지 않는다.
2. 소스가 있다면 패키지·잠금파일·실행 스크립트·앱 설정·서버·DB 스키마·테스트를 읽어 실제 기술구성과 실행 방법을 확정한다. 문서에 없는 버전, 명령, 경로, 계정, 파일을 만들어내지 않는다.
3. 원본과 별도의 작업 복사본에서 시작하고 기준 체크포인트/변경 파일을 기록한다. 원본 Replit, 데이터, 인증, 기존 API 키를 지우거나 바꾸지 않는다.
4. 기존 구현과 요구사항의 차이를 정리한 뒤 실제 오류 재현 → 원인 → 최소 수정 → 실행 → 재검증까지 진행한다. 계획이나 프롬프트 전달만을 실행으로 보고하지 않는다.

## 최우선 문제

Expo Go에서 QR 스캔과 8자리 로그인 코드 입력 후 미리보기를 눌렀을 때 앱이 열리지 않았고, Replit의 Android 기기 화면에는 `Something went wrong / View error log`가 보였다. 앞서 iPhone형 미리보기에는 `Failed to parse manifest JSON: The data couldn’t be read because it isn’t in the correct format.`가 나타났다. 웹 HTTP 200, 표준 manifest 200, 번들 생성 성공과 사용자 기기 첫 화면 성공은 다르다. 같은 요청 경로의 오류 로그와 응답 형식을 확인해라. Expo Go의 기본 실행 실패를 Apple/Firebase/푸시 서명 준비만 요구하며 종결하지 않는다. 실제 기기가 필요한 마지막 재현만 사용자에게 한 번에 요청한다.
