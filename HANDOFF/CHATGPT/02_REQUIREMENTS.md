## 디자인과 문구

각 화면은 짧은 제목 + 목적/상태 한 줄 + 대표 행동 버튼을 기본으로 한다. 긴 설명은 펼쳐보기로 정리하되 필수 조건, 마감, 이용권 제한, 동의, 탈퇴 영향, 회사 접수와 기관 신청의 차이는 기본 화면에도 짧게 남긴다. 글자를 작게 하거나 중요한 정보를 잘라 숨기지 않는다. 광고 문구를 반복하지 않는다.

상황별 문구 예시:
- 정보 입력: 맞는 혜택을 찾도록 정확히 알려주세요.
- 모름: 모르면 나중에 입력해도 돼요.
- 이어하기: 입력하던 곳부터 이어가세요.
- 실제 저장 성공: 저장했어요.
- 추가 확인: 이 조건을 더 확인해 주세요.
- 실제 회사 접수 성공: 회사에 요청이 접수됐어요.
- 서류: 지금은 이 서류를 준비해 주세요.

버튼은 다음 / 이어서 입력 / 정보 수정 / 저장하기 / 회사에 도움 요청 / 공식 신청 페이지 / 문의 보내기 / 다시 시도 등 행동 결과를 알 수 있게 쓴다. 실제 저장·접수·답변·발송이 성공해야 성공 문구를 표시한다. '무조건 지급', '100%', 근거 없는 금액 합계·인기 수치·긴급성을 쓰지 않는다.

## 프로필 입력과 회원

한 번에 한 질문, 큰 선택 버튼, 모름/나중에/뒤로/수정/저장 확인/이어하기를 제공한다. 사용자가 선택하거나 다음을 눌러 이동한다. 입력 없이 자동으로 다음 단계로 넘기거나 개인 정보를 추측해 채우지 않는다.

거주지와 사업장 소재지, 개인·가구와 사업자 정보를 분리한다. 업종·개업일·사업 상황을 다루고 근로자이면서 사업자인 겸업을 지원한다. 소득·매출·자산에는 기준기간/대상/단위와 읽기 쉬운 금액을 표시한다. 모름, 미응답, 해당 없음, 실제 0을 구분한다. 최소 기본정보부터 받고 관련 공고 판단에 필요한 것만 추가로 묻는다. 어려운 질문에는 이유 한 줄과 쉬운 용어 설명을 붙인다. 건강·자녀 등 민감 정보를 기본값으로 확정하지 않는다.

서버 저장 실패 시 성공 안내나 완료 이동을 하지 않는다. 실제로 보존된 경우에만 저장됐다고 안내한다. 중단·재로그인·재설치 후 서버에 저장한 값과 단계를 복원한다. 이전 답 수정 후 추천을 갱신한다. 입력 진행률은 저장된 입력 기준이고 수령 확률이 아니다. 미저장 상태의 여러 기기 동시 자동병합은 추가 필수 범위가 아니다.

무료 일반회원, 명시적 3일 체험, 관리자 연결 계약회원 상태를 유지한다. 필요한 최소 정보와 가입 후 '3일 무료체험 시작'을 직접 누를 때 1인 1회 연속 72시간을 시작한다. 서버 기준 시작/종료시각을 한국시간으로 보여주고 기기시계 변경·재로그인·재설치로 연장되지 않는다. 마케팅 거절·푸시 미허용으로 체험을 막지 않는다.

필수 서비스 개인정보 처리와 선택 마케팅 동의를 분리한다. 내용·버전·시각·철회를 기록한다. 알림 권한은 강제하지 않으며 상태 확인·설정 연결·앱내 알림함을 제공한다.

## 계약 이용권

관리자가 기존 169만원 연간 지원금 패키지 계약 고객에게 기간·근거를 기록해 이용권을 부여·연장·회수한다. 가격상품이나 온라인 결제 활성화 요청은 아니다. 신규 계약 고객은 체험 없이 바로, 기존 무료·만료 고객은 본인확인된 기존 계정에 연결해 재가입 없이 이용한다.

동명이인 이름만으로 연결하지 않는다. 정확한 계정 소유 확인과 서버 권한 검증을 사용한다. 고객의 자가 계약 생성·관리자 승격을 막는다. 무상 이용권과 계약 관리 권한을 분리하고 감사 이력을 남긴다. 체험 중 계약이 생기면 체험 만료와 무관하게 접근한다. 유효 권한이 겹칠 때 한 권한의 만료/회수가 다른 유효 권한을 없애지 않는다. 검증된 기존 이용권 데이터를 보존한다. 스토어 적합성·승인은 별도 검토 항목이며 승인 완료라고 하지 않는다.

## 공고 찾기·카드·상세

현재 공고와 지난 공고를 분리한다. 거주/사업장 적용 맥락을 가진 지역, 개인·가구·사업자 대상, 분야, 접수상태 필터와 제목/기관/키워드 검색을 제공한다. 추천/최신/마감임박 정렬, 선택 필터 표시·초기화, 실제 결과 수, 상세 왕복 후 스크롤/필터 유지를 연결한다. 인기/조회 통계가 없으면 최신순으로 대체한다.

카드는 읽히는 제목, 기관, 지역/대상, 지원내용, 실제 신청기간/접수상태, 짧은 추천 이유/확인 필요를 보여준다. 작은 보기 버튼에만 의존하지 않는다. 의미 없는 중복 추천 섹션을 정리한다.

상세 순서는 대상/지원/기간/신청처 → 내 조건과 맞는 점·확인할 점 → 서류·발급처 → 고객/직원 할 일 → 신청 순서 → 공식 출처·확인시각. 원문에 없는 자격·서류·금액·절차는 추측하지 않는다. 금액 미제공은 0원이 아니다. 상시/예산소진/미정/실제마감을 구분한다. 사업 운영기간의 연말을 신청 마감으로 대신하지 않는다. D-day는 확인된 마감시각을 기준으로 하며 원문과 날짜 충돌은 확인 필요다.

지난 공고는 조회시점 전에 실제로 마감된 자료다. 어제 공고라는 이유만으로 마감 처리하지 않는다. 2026년 1월부터 보유한 기간/지역/업종 범위를 안내하되 미수집 기간과 지역을 전국 전체처럼 표현하지 않는다. 당시 기준연도·나이·업력·소재지·매출·고용 등 과거 조건으로 판단한다. 없으면 '현재 입력정보 기준 참고' 또는 '당시 조건 확인 필요'다. '그때 가입했으면 받았을 돈'이나 놓친 돈 합계로 표현하지 않는다. 경쟁·예산·중복수혜에 따라 지급이 확정되지 않음을 짧게 표시한다. 마감 공고는 신청 불가. 관리자 고객 상세도 같은 판단 기준을 사용한다.

관심 저장/해제, 최근 본 공고, 마감 확인, 고객이 선택하는 공개공고/공식링크 공유·복사를 연결한다. 공유 링크에 개인정보·계정·토큰·내부 상담 내용을 넣지 않는다. 수신자의 접근권한도 검증한다. 자동 메시지는 보내지 않는다.

## 회사 접수·직원·진행

'회사에 도움 요청' 직전에 최신 입력·공고 조건·마감·중복·이용권을 다시 확인한다. 알려진 조건이 맞으면 고객 확인 후 회사 접수함에 실제 저장한다. 불일치는 어느 입력과 조건이 다른지 쉽게 설명하고 수정/문의 경로를 준다. 모름·정보 부족·원문 불명확·기관 판단은 자동 불가 대신 추가 확인 문의로 보낸다. 재클릭/재시도로 중복 저장하지 않는다. 저장 실패는 성공이 아니다.

내진행에는 접수·배정·자료준비·담당자확인·답변의 실제 상태, 최종 변경시각, 고객 할 일/직원 할 일/완료 내역·이력을 보여준다. 회사 접수를 정부기관 접수·승인·지급 완료로 표시하지 않는다.

관리자는 허용된 전체와 고객별 현재/지난 공고, 판단 근거, 부족정보, 진행상태를 보고 담당자를 배정/재배정한다. 직원은 본인에게 배정된 고객·접수만 접근한다. 재배정 후 이전 직원 권한을 회수하고 배정·상태변경 이력을 남긴다. 내부 메모와 다른 고객 문의를 노출하지 않는다.

직원 체크리스트에는 공식근거에 따른 해당 이유/추가 질문/서류·발급처/행동순서/고객 안내/마감/주의사항을 둔다. 모르는 내용은 확인 필요다.

## 연락과 웹 문의

관리자가 직원별 업무 전화번호와 카카오 상담 링크를 등록한다. 고객이 직접 눌러 연락한다. 미배정은 회사 문의로, 미등록/잘못된 번호·링크는 사용할 수 없는 상태로 안내한다. 자동 전화·메시지 발송은 없다.

동일 계정으로 앱과 프로젝트 내부 웹 문의에서 문의·건의·답변·상태를 저장하고 관리자/배정직원이 처리한다. 회사 문의 주소를 설정할 수 있어야 한다. 도메인이 없으면 미설정으로 표시하고 도메인을 구매하거나 공개 배포하지 않는다. 체험 종료 후에도 본인 문의·개인정보 권리 행사·탈퇴 경로는 유지한다. 회사 정책 전체 편집 화면이 있다고 가정하지 않는다.

## 알림과 접근통제

유효 체험/계약 고객에게 실제 검토·공개된 새 맞춤공고만 조건에 맞게 제공한다. 발송 직전 이용권/동의/마감을 확인한다. 만료·회수·탈퇴·동의 철회 후 예약 알림, 오래된 링크, 알림함·화면 캐시에서 맞춤 내용이 새로 노출되지 않게 한다.

유효 권한이 없으면 맞춤 현재/과거/알림을 잠그지만 일반 무료목록·상세와 본인 문의는 허용한다. 다른 유효 계약이 있으면 체험만료와 무관하게 유지한다.

알림 허용 상태/설정 연결/앱내 알림함/빈 상태와 미연결·거절·발송실패·제공자접수·수신미확인을 구분한다. 기존 실패 안내 구현은 보존한다. 실제 수신 전에 도착했다고 하지 않는다.

Expo iOS/Android 푸시와 알림 클릭 시 공고 상세 진입을 준비한다. 잠금화면에 민감 자격정보/금액을 표시하지 않는다. OS 권한·집중모드·항상 소리를 강제하지 않는다. FCM/APNs·서명·실기기가 없으면 실수신 미검증으로 남긴다. 실제 고객에게 시험 알림을 보내지 않는다.

## 공식 API와 품질

기업마당, 정부24, 복지로 중앙/지자체 4종 키는 기존 Replit에 등록됐고 공식 소량 읽기 성공 이력이 있다. 키 존재·승인·할당량·호출 성공·저장·검토 공개는 구별한다. 각 최신 공식 명세와 실제 계정의 범위/한도를 확인한다. 공고 API를 개인별 환급금 조회 API라고 취급하지 않는다.

관리자에 신규·수정·중복·제외·실패·미승인·누락범위·마지막 성공시각을 표시한다. 실패/빈 응답으로 정상 최신 자료를 덮어쓰지 않는다. 한도·페이지·재시도·공급자 간 중복·제외 분류를 검사한다. 고객 접속마다 외부 API를 새로 호출하지 않는다.

저장된 검토대기 3건의 원문/조건/기간/서류 대조와 잘못된 요약 수정 여부를 확인한다. 실제 계정 한도와 이용조건이 불명인 공급자 자동수집을 임의 활성화하지 않는다. 미검토 자료 자동공개·실고객 알림도 금지. 모르는 한도를 만들어내지 않는다. 개발 서버 중단 시 주기 수집도 멈출 수 있다. 시험공고와 운영 자료를 분리한다.

## 실행·장애 상태

기본 실행으로 앱/API가 함께 올라오게 하고 종료시각·이유·생존 근거를 보존한다. 이전 HTTP 502 반복을 같은 단순 재시작으로만 대응하지 않는다. 코드/개발환경 수명/정리작업/포트 충돌/자원제약을 근거로 구분한다. 유료 배포 없이 가능한 경로와 최소 실행법을 제시하고 상시가동을 보장하지 않는다.

목록·상세·문의·외부 이동에서 로딩/빈 결과/미수집/오프라인/시간초과/잘못된 링크를 구분하고 재시도/뒤로/기본브라우저/주소복사를 제공한다. 외부 복귀 시 필터/스크롤을 보존한다. 외부 사이트를 열었다고 신청 성공으로 처리하지 않는다. 고객 화면에는 짧은 행동 안내, 개발 로그에는 필요한 진단을 남기되 비밀값은 제외한다.

## 비교 영상의 활용

참고 영상은 약 150.7초의 사용자가 제공한 지급24 화면이다. 00:32~01:25의 한 문항 입력, 큰 선택지, 사용자가 직접 다음으로 넘어가는 흐름, 탐색 필터·정렬, 간략 상세와 공식 이동을 참고한다. 백엔드 동작이나 실지급/실푸시는 영상으로 검증되지 않았다.

개선 목표: 근거 없는 금액/숫자 제거, 기간 모순과 마감 오표시 방지, 텍스트 과밀 완화, 저장/접수/빈 화면/외부 이동 실패를 구분. 후반 빈 알림함·내정보 화면도 개선 대상으로 본다. 외부 흰 화면에는 Safari 개인정보 브라우징 잠금이 포함되어 있어 모두 비교 앱 결함으로 단정하지 않는다. 디자인 자산·상표·문구를 그대로 베끼기보다 사용성의 장점을 이 앱에 맞게 구현한다.

## 완료 판단

변경 영향과 남은 위험만 의미 있게 검사한다. 시간 상한으로 중단된 검사는 완주라고 하지 않는다. 웹/서버/모의/공식 실호출/번들/실기기를 구분한다. 실제 첫 화면·로그인·고객/직원/관리자 핵심 화면을 확인한다. 가능한 접속 경로, 남은 코드 문제, 외부 설정을 나눠 한국어로 보고하고 사용자만 할 일을 마지막 한 목록으로 정리한다.
